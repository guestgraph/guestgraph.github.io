How it decides

Matching is easy. Being wrong is expensive.

Merge two guests wrongly and one person sees another's stays and invoices. That is a data protection incident, not a cosmetic flaw — so nothing merges on a hunch. Each layer decides only what it can justify and hands the rest upward.

01

A shared strong identifier

The same email, phone, loyalty id or ID document. Merges outright, at full confidence.

02

A probabilistic score

Similar names, matching birthdate, the same last seven phone digits. Merges only above a threshold you chose — and automatic merging ships switched off.

03

A person

Everything else queues for a human, with a per-signal breakdown of why it scored what it scored. Their decision sticks: an undo writes a rule that new evidence cannot quietly cross.

Every merge can be explained and undone — that shipped before any uncertain decision was possible.

Where it stands

The engine is built. Almost nothing else is.

This is a foundation, not a product. Worth knowing before you spend ten minutes on the talk.
